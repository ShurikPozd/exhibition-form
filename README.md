# Анкета участника выставки

Веб-приложение для сбора заявок на выставке: посетитель заполняет анкету на iPad прямо
на стенде, организатор после выставки скачивает **Excel** или **CSV**, а при желании —
**Google-таблицу**, которая заполняется сама.

Никаких регистраций и паролей для посетителя: одна страница, одна кнопка «Отправить».

## Что умеет

- **Анкета как в макете**: 10 блоков, чекбоксы в две колонки или в один ряд, поля крупные
  (попадать пальцем на iPad — приятно).
- **Черновик**: если посетитель отвлёкся, данные лежат в `localStorage` и восстанавливаются
  при следующем открытии.
- **Надёжное сохранение**: после `commit` заявка перечитывается из базы — «201 Created»
  выдаётся только тогда, когда запись действительно легла в SQLite.
- **Выгрузка в Excel** (`.xlsx`) двумя листами: «Заявки» (по строке на анкету) и
  «Подробно» (по строке на каждый отмеченный пункт — так можно строить сводки).
- **Выгрузка в CSV** в кодировке UTF-8 с BOM и разделителем `;` — русский Excel открывает
  без плясок с кодировками.
- **Синхронизация с Google Sheets** через вебхук Apps Script: без OAuth и ключей Google
  Cloud. Синхронизация не обязательна: если Google недоступен, приём анкет не страдает.
- **Защищённая админка**: список заявок, кнопки скачивания и повтор отправки в Google
  закрыты секретным токеном.
- **Подсказки под полями**: имя, телефон, email и согласие подсказывают, что ещё нужно,
  прямо при вводе (сколько цифр в телефоне, похож ли адрес почты). Номер приводится к виду
  `+7 (999) 123-45-67` только если посетитель уже набрал код страны (7 или 8) — и больше
  ничего: страна по цифрам не угадывается, поэтому номер из другой страны сохраняется
  ровно таким, каким его ввели. Сервер проверяет только длину (10–15 цифр, как в E.164).
- **Два языка, русский и английский**: в правом верхнем углу переключатель
  `Русский | English`. Английская версия показывает и текст согласия, и подсказки под
  полями, и сообщения об ошибках — целиком, без русских остатков. Страница запоминает
  язык в адресе (`?lang=en`), поэтому её можно повесить на отдельную ссылку для иностранцев.
- **Один словарь значений**: в базу, в Excel и в админку всегда попадает русское значение
  варианта, английским является только подпись на экране. Благодаря этому база,
  выгрузка и проверки сервера не знают про языки, а новый язык не требует миграции.
- **Экран «Спасибо» с автосбросом**: через 3 секунды после отправки форма очищается сама —
  перед следующим посетителем ничего нажимать не нужно. Если нужно заполнить ещё одну
  анкету не сразу, есть кнопка «Начать сейчас».
- **Печать бланка**: на странице есть стиль для печати A5 — можно распечатать пустую анкету
  для бумажного варианта; чекбоксы печатаются вместе с отметкой выбранного варианта.

## Быстрый старт

```powershell
# 1. Виртуальное окружение и зависимости
python -m venv .venv
.\.venv\Scripts\pip.exe install -r requirements.txt

# 2. Настройки
copy .env.example .env
#    впиши в .env свой EXPORT_TOKEN (обязательно) и реквизиты оператора ПДн

# 3. Запуск
.\.venv\Scripts\python.exe -m uvicorn app:app --host 0.0.0.0 --port 8000
```

Анкета: <http://127.0.0.1:8000/> · админка: <http://127.0.0.1:8000/admin?token=ВАШ_ТОКЕН>

## Docker

```powershell
copy .env.example .env
#    впиши в .env свой EXPORT_TOKEN (обязательно) и реквизиты оператора ПДн

docker volume create exhibition_data   # один раз: том с заявками
docker compose up -d --build
```

Дальше — `docker compose logs -f`, `docker compose restart`, `docker compose down`
(том и заявки при этом остаются).

Как это устроено и почему так:

- **Секреты только в `.env`**, а `docker-compose.yml` их не содержит и подключает файл
  через `env_file`. Поэтому compose-файл можно спокойно коммитить, а токен админки и
  секрет вебхука в git не попадут.
- **База — на томе `exhibition_data`, подключённом в `/app/data`** (именно `/app/data`:
  приложение по умолчанию пишет в `data/` рядом с собой, и без монтирования заявки жили
  бы только внутри контейнера). Том объявлен как `external`, поэтому Compose не считает его
  своим и не удаляет при `down`.
- **`restart: unless-stopped`** — после перезагрузки Windows или перезапуска Docker анкета
  поднимается сама.

Если хотите запустить контейнер вручную, минуя compose, монтирование всё равно должно быть
`-v exhibition_data:/app/data`, а все переменные передаваться флагами `-e`: внутрь образа
`.env` не копируется (его исключает `.dockerignore`), и `load_dotenv()` в контейнере файла
не найдёт.

## Настройки (.env)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `HOST`, `PORT` | адрес и порт запуска | `0.0.0.0`, `8000` |
| `LOG_LEVEL` | уровень логов (`INFO`, `DEBUG`…) | `INFO` |
| `DATA_DIR` | папка с файлом SQLite | `./data` |
| `DATABASE_URL` | полный URL БД, если нужен другой бэкенд | `sqlite:///<DATA_DIR>/submissions.db` |
| `EXPORT_TOKEN` | токен доступа к `/admin` и выгрузке. **Обязателен** | нет — выгрузка отдаёт 403 |
| `GOOGLE_SHEET_WEBHOOK_URL` | URL вебхука Apps Script | нет — синхронизация выключена |
| `GOOGLE_SHEET_SECRET` | секрет, который проверяет вебхук | нет |
| `GOOGLE_SYNC_ENABLED` | `false` — не синхронизировать вовсе | `true` |
| `GOOGLE_SHEET_TIMEOUT` | таймаут запроса к Google, секунд | `5` |
| `CONSENT_OPERATOR_NAME` | кто обрабатывает персональные данные | «организатор выставки» |
| `CONSENT_OPERATOR_EMAIL` | куда писать об отзыве согласия | нет |
| `CONSENT_OPERATOR_ADDRESS` | адрес хранения данных | нет |

## Выгрузка

Все три ручки закрыты `EXPORT_TOKEN`. Токен передаётся заголовком `X-Export-Token`
(удобно для скриптов) или параметром `?token=` (удобно, чтобы скачать файл ссылкой).

| Адрес | Что отдаёт |
|---|---|
| `/admin` | список заявок, кнопки скачивания, повтор синхронизации |
| `/api/submissions.xlsx` | Excel: листы «Заявки» и «Подробно» |
| `/api/submissions.csv` | CSV (UTF-8 BOM, `;`) |
| `/api/submissions` | JSON с теми же колонками |
| `POST /api/google/sync` | повторная отправка всех неотправленных заявок |
| `POST /api/google/sync/{id}` | повтор для одной заявки |

## Google Sheets за 5 минут

Нужен только аккаунт Google — без Google Cloud, OAuth и API-ключей:

1. Открой <https://script.google.com> → «Новый проект».
2. Вставь код из [`docs/google-apps-script.gs`](docs/google-apps-script.gs) вместо `Code.gs`.
3. Впиши `SECRETS.SHEET_TOKEN` (тот же секрет, что в `.env`) и `SECRETS.SPREADSHEET_ID`
   (ID таблицы из адреса `…/d/<ID>/edit`).
4. «Развернуть» → «Новое развёртывание» → тип «Веб-приложение» → «Выполнять от моего
   имени» → «Доступ: для всех».
5. Скопируй адрес `…/exec` в `.env` как `GOOGLE_SHEET_WEBHOOK_URL`, секрет — как
   `GOOGLE_SHEET_SECRET`, и перезапусти приложение (`docker compose up -d` или перезапуск
   локального процесса).

Пустая таблица заполнит шапку сама при первой заявке. Порядок колонок совпадает с
выгрузкой Excel; сверить его можно командой:

```powershell
.\.venv\Scripts\python.exe -m tools.print_headers
```

Если вебхук недоступен, заявка всё равно сохранится, а её статус появится в колонке
`google_synced_at` и в тексте ошибки `google_error` — повторить можно кнопкой в `/admin`.

## Как устроено

```
app.py                 точка входа: роутеры, статика, healthcheck, логирование ошибок
config/form_fields.py  описание анкеты — единственный источник правды
schemas.py             валидация входящих данных (Pydantic)
models.py              таблица submissions
database.py            движок SQLite, WAL, сессии
services/submissions.py сохранение и выборка заявок
services/exporters.py  колонки выгрузки, .xlsx и .csv
services/google_sheet.py синхронизация с Google Sheets
services/form_view.py  сбор контекста шаблона
config/i18n.py        языки анкеты: код языка, переводы строк, текст согласия
config/translations/  по модулю на язык: ru.py (строки интерфейса), en.py (перевод)
handlers/form.py       GET / и POST /api/submissions
handlers/admin.py      админка и выгрузка
templates/             form.html, admin.html
static/                css и js формы
tools/print_headers.py печать колонок выгрузки
docker-compose.yml    запуск в контейнере: образ, порт, том с базой, env_file
docs/google-apps-script.gs скрипт для Google Sheets
tests/                 87 тестов: поля, API, доступ, выгрузка, Google, языки
```

Данные лежат в одной таблице `submissions`. Контактные поля (`name`, `company`, `phone`,
`email`) вынесены в отдельные колонки, чтобы по ним можно было фильтровать обычным SQL,
а остальные ответы лежат в JSON-поле `payload`: набор пунктов анкеты меняется от выставки
к выставке, и под каждый чекбокс колонку заводить незачем.

### Как поменять анкету

Правьте только `config/form_fields.py`: форму, валидацию и колонки выгрузки собирает он.
Например, чтобы убрать согласие на ПДн, удалите поле с `type` = `consent` из списка
`FORM_FIELDS` — в форме, проверках и выгрузке оно исчезнет само.

### Два языка, один словарь значений

Русский вариант — родной: заголовки полей и формулировки вариантов лежат в
`config/form_fields.py`, а значения чекбоксов **одновременно** служат подписью и данными
для выгрузки. Поэтому переводится только текст, а значение остаётся русским:

| Что | Где | Правило |
|---|---|---|
| Заголовки полей, плейсхолдеры, подсказки | `config/translations/en.py` | перевод; нет перевода — покажется русский |
| Значения чекбоксов | `config/form_fields.py` | **не переводятся**: `value` в HTML и в базе всегда русский |
| Кнопки, экран «Спасибо», подписи | `config/translations/*.py`, секция `ui` | перевод |
| Подсказки под полями и статусы | секция `js` → `<script id="i18n">` | перевод; ключ ищется через `t()` |
| Текст согласия | секция `consent` | перевод, версия согласия одна на все языки |
| Ответы сервера про чужой вариант | секция `server` | перевод по ключу поля; нет перевода — ответ как есть |

Добавить язык — значит завести `config/translations/<код>.py` с тем же набором секций,
дописать код в `LANG_NAMES` в `config/i18n.py` и продублировать пару тестов из
`tests/test_i18n.py`. Тест `test_translation_bundles_agree_on_keys` упадёт, если в новом
наборе не хватает ключа, который есть в русском, — это дешевле, чем молча пропавший текст.

Что сознательно **не** переводится: админка, выгрузка Excel/CSV и колонки базы. Там работает
менеджер, который мыслит по-русски, и хранить две версии одного ответа в базе — верный путь
к расхождениям в выгрузке.

## API

| Метод | Адрес | Назначение |
|---|---|---|
| `GET` | `/` | анкета (русский) |
| `GET` | `/?lang=en` | анкета на английском; неизвестный код языка → русский |
| `POST` | `/api/submissions` | отправить заявку (422 с текстом ошибок при неверных данных) |
| `GET` | `/healthz` | проверка живости |
| `GET` | `/api/docs` | автоматическая документация OpenAPI |
| — | `/admin`, `/api/submissions.*`, `/api/google/*` | закрыты `EXPORT_TOKEN` |

Пример заявки:

```json
{
  "name": "Иван Петров",
  "company": "ООО Ромашка",
  "role": ["интегратор", "другое"],
  "role_other": "журналист",
  "stall": ["материалы о продуктах"],
  "directions": ["SmartHome"],
  "interest": ["Нужно КП, презентация, встреча или партнерство"],
  "phone": "+7 999 123-45-67",
  "email": "ivan@example.com",
  "after_show": "Прислать прайс",
  "consent": true
}
```

Правила проверки: имя обязательно; телефон **или** email обязателен; отметили «другое» —
нужно уточнение; согласие на ПДн обязательно; неизвестный вариант чекбокса — 422.

## Персональные данные

- Заявка — это персональные данные, поэтому админка и выгрузка закрыты токеном
  «fail-closed»: если `EXPORT_TOKEN` не задан, ручки отдают 403 с объяснением, а не
  открываются.
- В логи пишутся только маскированные телефон и email, без содержимого свободных полей.
- В лог ошибок попадает текст исключения (его видно в консоли администратора), но клиенту
  отдаётся нейтральное «внутренняя ошибка сервера».
- Версия текста согласия сохраняется вместе с каждой заявкой — видно, на каких условиях
  человек дал согласие.
- Что делать с базой после выставки (удалить, архивировать, продлить срок хранения) —
  решение оператора; в коде есть только экспорт, удаления намеренно нет.

## Проверки

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check_code.ps1
```

Скрипт гоняет `black` (формат), `flake8` (линтер) и `pytest` (тесты). Тесты используют
отдельную временную базу, поэтому рабочие заявки не затрагиваются, и подменяют `httpx.post`,
так что сеть не нужна.

## Ограничения

- SQLite рассчитан на один сервер: файл базы лежит на диске, горизонтальное масштабирование
  не предусмотрено. Для выставки этого хватает с запасом.
- Синхронизация с Google best-effort: если вебхук недоступен в момент отправки, запись
  попадёт в таблицу только после нажатия кнопки повтора в админке.
- Форма рассчитана на iPad и обычный браузер; печать в A5 — запасной сценарий, а не основной.
- Пункт 9 анкеты («Выслать/сделать после выставки») — свободный текст без уточнений от
  заказчика: если станет ясно, что нужно выбрать один из вариантов, добавь поле
  `checkbox_group` в `config/form_fields.py`.
